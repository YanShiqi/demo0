# 每周签到功能设计

## 目标与范围

为已登录用户提供轻量的每周签到功能。每个用户在网站配置时区内每周只能签到一次，成功签到获得 1 个配置货币（当前展示名称为“洲币”）。第一版只做每周领取、签到记录和货币审计，不做连续签到、补签、排行榜、额外奖励或管理员代签。

## 周期规则

- 使用 `[display].utc_offset_hours` 作为网站业务时区，当前为 UTC+8。
- 每周一 00:00 开始新周期，到下周一 00:00 前结束。
- 服务端将当前 UTC 时间转换为网站时区，再计算本周周一的本地日期。
- `week_start` 使用 `YYYY-MM-DD` 保存，不依赖数据库日期函数或 SQLite 方言。
- 周期计算由可注入当前时间的纯函数完成，测试覆盖周日、周一及跨年边界。

## 配置

在 `config/default.toml` 增加：

```toml
[check_in]
# 是否开启每周签到功能；关闭后首页不展示入口，签到端点也不接受请求。
enabled = true
# 每周签到成功后发放的整数货币数量。
reward_amount = 1
```

同时支持 `CHECK_IN_ENABLED` 和 `CHECK_IN_REWARD_AMOUNT` 环境变量覆盖。奖励必须为正整数。货币名称和符号继续读取 `[currency]`，签到业务不依赖“洲币”文字。

## 数据模型

新增 `weekly_check_ins`：

```text
id             CHAR(26) PRIMARY KEY
user_id        CHAR(26) NOT NULL REFERENCES users(id)
week_start     VARCHAR(10) NOT NULL
reward_amount  BIGINT NOT NULL
created_at     VARCHAR(40) NOT NULL
UNIQUE(user_id, week_start)
```

`reward_amount` 保存实际发放值，配置以后改变也不会影响历史记录。唯一约束是并发和重复请求的最终保障。用户删除时签到记录随用户删除。所有业务 SQL 使用参数绑定并尽量保持可移植。

## 签到与货币事务

新增签到领域模块，负责周期计算、状态查询和签到事务。签到端点只负责会话、CSRF 和重定向，不直接修改余额。

成功流程：

1. 验证签到功能已开启并取得当前用户。
2. 按网站时区计算 `week_start`。
3. 开启数据库事务并创建签到记录。
4. 调用统一货币服务发放配置数量的货币。
5. 写入原因 `weekly_check_in` 的货币流水；`related_id` 使用签到记录 ID，`operator_user_id` 使用用户自身。
6. 使用 `weekly-check-in:{user_id}:{week_start}` 作为稳定幂等键。
7. 提交事务后返回首页。

签到记录、余额和货币流水必须同时成功或同时回滚。重复请求返回“本周已签到”，不再次发放货币。余额溢出、流水写入或数据库操作失败时，不保留签到记录。

## 页面设计

签到区域放在登录后首页“首页动态”标题右侧，与标题共用 `preview-heading`。桌面端显示为紧凑状态卡，窄屏自动换到标题下方。

- 未签到：显示“本周签到”、奖励“🪙 1 洲币”和“签到领取”按钮。
- 已签到：显示“本周已签到”和“下周一可再次签到”，不显示可提交按钮。
- 签到成功：重定向首页并显示简短成功提示，同时页面立即切换为已签到状态。
- 配置关闭：不渲染签到区域；直接请求签到端点返回不存在，避免暴露不可用操作。

按钮使用 POST 并携带现有 CSRF token。前端不能提交奖励数量、用户 ID 或周期，所有值由服务端决定。

## 权限与安全

- 只有已登录且不处于强制修改密码状态的用户可以签到。
- 普通用户、管理员和超级管理员遵循相同的每周限制。
- 数据库唯一约束和货币幂等键共同防止双击、重试及并发重复领取。
- 不提供管理员修改签到记录或补发签到奖励的入口；必要的人工补偿继续使用超级管理员货币调整功能。

## 测试与发布记录

测试覆盖首次签到、同周重复签到、并发请求、功能关闭、配置奖励值、周一边界、跨年周、CSRF、未登录请求，以及签到记录与货币流水内容。首页测试覆盖未签到、已签到、成功提示和窄屏所需的结构化样式类。

该功能包含新用户功能、配置组、数据库迁移和货币行为变化，实施时必须按照仓库规则在 `content/updates.toml` 添加服务器更新记录。
