# 服务器更新记录设计

## 目标

在首页新增一个与“首页动态”平行的“服务器更新记录” section，并提供 `/updates` 查看全部记录。更新内容由仓库文件维护，不写入 SQLite，也不增加后台管理功能。

## 数据与配置

- 新增 `content/updates.toml`，每条记录包含 `date`、`version`、`title`、`summary` 和 `changes`。
- 记录按日期倒序展示；日期使用 `YYYY-MM-DD`，解析失败时在启动阶段返回明确错误。
- 新增 `[updates]` 配置：`file` 指向数据文件，`home_preview_limit` 控制首页最多展示数量。配置项和数据字段均添加中文注释。
- 文件不存在、TOML 格式错误或记录字段无效时，服务器启动失败并给出文件路径和错误原因。

## 页面与数据流

- 首页对所有访客展示独立 section，不受登录状态影响；默认展示最近 3 条并提供“查看全部”链接。
- `/updates` 使用服务端渲染展示全部记录，每条记录显示版本、日期、标题、摘要和变更列表。
- 更新数据在应用状态中只读加载，首页使用预览切片，避免每次请求重复读取文件或加载无关内容。
- 记录为空时显示友好的空状态，不渲染空卡片。

## 测试与约束

- 单元测试覆盖 TOML 解析、字段校验和日期排序。
- 集成测试覆盖匿名首页可见、首页预览数量限制和 `/updates` 全量展示。
- 遵守仓库规则：关键逻辑添加中文注释，字面量提取为配置或命名常量，避免 SQLite 方言。
