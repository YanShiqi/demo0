# Meme 审核奖励货币设计

## 目标

当用户提交的 Meme 首次通过管理员审核时，向该 Meme 提供者发放 1 个配置货币（当前展示名称为“洲币”）。奖励必须可审计、不可重复发放，并且不能破坏现有审核流程。

## 规则

- 只有 `pending` → `approved` 的状态迁移会触发奖励。
- 奖励数量默认配置为整数 1，不使用浮点数；通过配置可关闭或调整。
- Meme 被重复审核、已通过后再次操作、删除后重新处理，都不能再次产生同一审核奖励。
- 奖励流水使用独立原因 `meme_approval_reward`，记录提供者、审核者、Meme ID 和备注。
- 奖励发放失败时，审核状态更新和货币变动一起回滚；不能出现“已通过但未奖励”。

## 配置

在 `[memes]` 增加并提供中文注释的配置项：

```toml
# Meme 首次审核通过时是否发放奖励。
approval_reward_enabled = true
# 每个 Meme 首次通过时发放的整数货币数量。
approval_reward_amount = 1
```

奖励名称和符号仍由 `[currency]` 配置控制，业务逻辑不依赖“洲币”文字。

## 数据流与事务

审核处理器校验管理员和 CSRF 后，开启一个数据库事务。服务层使用带状态条件的更新：只有目标 Meme 当前为 `pending` 时才改为 `approved` 并写入审核者和审核时间；受影响行数为 0 时不发奖励，避免重复点击重复发放。状态更新成功后，调用统一货币服务写入正向流水，`related_id` 使用 Meme ID，`idempotency_key` 使用稳定的 `meme-approval:{meme_id}`。两个写入完成后才提交事务。

货币流水继续使用现有的 `currency_logs` 审计结构。奖励操作的 `operator_user_id` 为审核管理员，`user_id` 为 Meme 提供者，`balance_after` 记录发放后的余额。

## 错误处理

- Meme 不存在、已删除或不是待审核状态时，不修改余额。
- 提供者已不存在时，审核事务失败并回滚。
- 余额溢出、货币配置非法或流水唯一键冲突时，审核操作返回错误并回滚。
- 前端不额外提供“领取奖励”按钮，奖励完全由审核状态迁移触发。

## 测试

- 首次审核通过后，提供者余额增加 1，并产生 `meme_approval_reward` 流水。
- 再次审核同一个 Meme，审核状态和余额均不重复变化。
- 奖励开关关闭时，Meme 仍可正常通过，但不增加余额。
- 奖励数量使用配置值，而不是代码中的固定数字。
- 审核失败或奖励写入失败时，状态、余额和流水保持事务一致。
- 普通管理员和超级管理员都遵循现有 Meme 审核权限；不扩大删除或用户管理权限。
